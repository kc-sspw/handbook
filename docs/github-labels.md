# Etykiety projektów KC SSPW

Dla repozytoriów projektowych stosujemy mały, konsekwentny zestaw etykiet.

## Typ

- `type:bug` — błąd,
- `type:feature` — nowa funkcja,
- `type:task` — zadanie techniczne lub organizacyjne w repo,
- `type:docs` — dokumentacja.

## Priorytet

- `priority:P0` — krytyczne,
- `priority:P1` — wysokie,
- `priority:P2` — normalne,
- `priority:P3` — niskie.

## Blokady

- `blocked` — zadanie nie może ruszyć bez zewnętrznej decyzji, dostępu lub zależności.

Każde Issue powinno mieć co najmniej etykietę typu. Priorytet nadajemy tylko wtedy, gdy został rzeczywiście ustalony; brak priorytetu nie oznacza P2.

> Aktualna integracja GitHub nie udostępnia operacji tworzenia definicji etykiet w repozytorium, więc ten zestaw jest standardem do zastosowania przy tworzeniu repozytoriów.
