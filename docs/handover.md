# Przekazanie projektu

Projekt nie powinien przestawać być utrzymywalny tylko dlatego, że zmienia się osoba odpowiedzialna albo kończy się kadencja.

Przed przekazaniem sprawdź poniższą listę.

## Kod i repozytorium

- [ ] README opisuje aktualny stan projektu.
- [ ] Instrukcja uruchomienia działa.
- [ ] Wiadomo, która gałąź jest używana do wdrożeń.
- [ ] Otwarte Issues odzwierciedlają rzeczywiste zaległości.
- [ ] Nie ma potrzebnych informacji wyłącznie w prywatnych wiadomościach.

## Infrastruktura i integracje

- [ ] Udokumentowano używane usługi i integracje.
- [ ] Wiadomo, gdzie znajdują się konfiguracje i sekrety.
- [ ] Co najmniej jedna kolejna uprawniona osoba ma potrzebny dostęp.
- [ ] Nie ma zależności od prywatnego konta jednej odchodzącej osoby, jeśli można tego uniknąć.

Nie wpisuj do handbooka ani README samych sekretów — dokumentuj miejsce i sposób zarządzania nimi.

## Wiedza

- [ ] Opisano najważniejsze decyzje architektoniczne.
- [ ] Znane problemy i ograniczenia są zapisane.
- [ ] Nowy opiekun wie, jak uruchomić projekt lokalnie.
- [ ] Nowy opiekun wie, jak wygląda wdrożenie i podstawowa diagnostyka.

## Po przekazaniu

Usuń zbędne dostępy poprzednich opiekunów zgodnie z aktualnymi rolami w Komisji i SSPW.
