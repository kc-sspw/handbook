# Onboarding

Ten dokument opisuje minimalny zestaw informacji dla osoby, która zaczyna pracę przy projektach Komisji Cyfryzacji SSPW.

## 1. Konto GitHub

Do pracy używaj własnego konta GitHub. Nie współdziel kont użytkowników między osobami.

Po dodaniu do organizacji sprawdź, czy widzisz repozytoria potrzebne do swojej pracy. Dostęp powinien wynikać z roli lub zespołu, a nie z przypadkowo nadanych wyjątków.

## 2. Zanim zaczniesz

Zapoznaj się z:

- README repozytorium,
- otwartymi Issues i Pull Requestami,
- instrukcją uruchomienia projektu,
- dokumentacją środowiska lub wdrożenia, jeśli istnieje.

Jeśli czegoś nie ma albo instrukcja jest nieaktualna, potraktuj to jako rzecz wartą poprawienia.

## 3. Podstawowy workflow

W utrzymywanych projektach domyślnie:

1. wybierz lub utwórz Issue,
2. utwórz branch,
3. wykonaj zmianę,
4. otwórz Pull Request,
5. poproś o review,
6. po merge usuń branch, jeśli nie jest już potrzebny.

W repozytoriach szkoleniowych workflow może być znacznie prostszy.

## 4. Minimalne narzędzia

W zależności od projektu przydadzą się:

- Git,
- GitHub,
- edytor kodu,
- runtime lub SDK używany przez projekt,
- narzędzia opisane w README konkretnego repozytorium.

Nie zakładaj, że nowa osoba zna wszystkie narzędzia. Dobra dokumentacja powinna umożliwić uruchomienie projektu bez wiedzy przekazywanej wyłącznie ustnie.

## 5. Gdy utkniesz

Najpierw sprawdź README, Issues oraz dokumentację projektu. Jeśli problem nadal jest niejasny, zapytaj opiekuna projektu albo osobę prowadzącą szkolenie.

Jeżeli rozwiązanie problemu może przydać się kolejnym osobom, dopisz je do dokumentacji.
