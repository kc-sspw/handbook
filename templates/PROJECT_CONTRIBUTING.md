# Contributing

1. Dla większej pracy zacznij od Issue.
2. Pracuj na osobnym branchu.
3. Otwórz Pull Request z krótkim opisem: co, dlaczego i jak sprawdzić.
4. Nie commituj sekretów, tokenów ani prawdziwych danych dostępowych.
5. Jeśli zmiana wpływa na wymagania lub architekturę, zaktualizuj odpowiedni dokument lub ADR.
6. W utrzymywanych projektach ważniejsze zmiany powinny przejść co najmniej jedno review przed merge.
